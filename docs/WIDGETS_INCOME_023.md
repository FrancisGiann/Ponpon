# Ponpon 0.2.3 scope and proof

Continue the saved 0.2.3 work from 0.2.2 without discarding it. Preserve the matte Inter/Cupertino cream/plum/dark world, existing spring routes, immediate input and reduced-motion support. No Liquid Glass, ad changes, Git push, publication or release creation.

Two separate Android 2 × 2 providers: compact category entry and tracked balance. Keep the original larger provider, metadata and layouts. The balance snapshot uses the existing active-wallet aggregate, with negative balances included and archived/removed wallets excluded. Amount visibility is opt-in and independent of Private app previews. A backup restore does not enable amount visibility. Refresh on successful ledger/preferences writes and app initialization/resume; no exact-time background updating is claimed. A tap opens the normal Add-entry draft, and every record still requires an explicit named-wallet save. No native link supplies a wallet or amount.

Home groups nonzero balances, including negatives, before zero balances while retaining source order within each group. All three wallets are shown at both standard and enlarged type. More than three uses the established compact preview with View all and a remaining count; the breakdown uses the same display grouping. Stored wallet order, direct-button order and financial formulas are unchanged.

Income chooses General income immediately. Its strip and full picker show General income, Allowance, Salary, Gift and Other income, plus user-created income-icon categories. Expense shows only expense categories. Changing type clears an incompatible category; a return to Income defaults to General income. Income category widget links infer the correct entry type. Existing IDs and category names in saved ledgers remain intact; legacy Income is displayed as General income in the new-entry picker. Missing built-ins are inserted atomically only when used to save a record. No migration rewrites transactions or category history. An unchanged historical cross-type category can be retained during edit; explicitly switching type uses the new default. The existing 100-category limit remains enforced.

Proof uses generated synthetic ledger fixtures only. Flutter captures are test-engine renders. Native fixtures are actual RemoteViews rendered by Robolectric; the debug-only AppWidgetHost is available for future Android 35 proof, but the attempted emulators terminated before a valid capture. There is no emulator or launcher-placement proof in this delivery. The helper activity is excluded from release builds. Physical POCO, launcher cell allocation/insets, TalkBack, haptics, SAF, predictive Back, and frame pacing require separate hardware validation.

Android sizing follows the official [App widgets guidance](https://developer.android.com/develop/ui/views/appwidgets/overview): hosts choose cell geometry, so the declared 2 × 2 target and minimum sizes are verified separately from real launcher placement.

Authorized final icon replacement: wallet is the primary mark, with a restrained folded-ear detail and one coin in plum/cream. SVG master and Android foreground/monochrome vectors are authoritative; legacy density PNGs, widget mark and Flutter branding are consistent derivatives. Prior dog-profile assets are preserved only in history. No old-icon 0.2.3 APK was delivered.
